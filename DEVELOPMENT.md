## 1. Текущая архитектура и фокус

- **Бэкенд**: Cloudflare Worker (`src/index.ts`)
  - Роуты: `/api/chat`, `/api/models`, `/templates/inspiration`, Telegram webhook `/bot-update`, `/setup`, статика.
  - Поддержка нескольких провайдеров моделей:
    - Cloudflare Workers AI (Llama-3.3-70b, Llama-3-8b, Llama-4-Scout-8b).
    - Hugging Face (Qwen-2.5-72b, Mistral-7b).
    - Ollama (Deepseek-Coder-V2, Llama-3.1-8b).
  - Нормализация ответов в формат `{ response: string }`.
  - Rate limiting через KV Storage.
  - Fallback модели и retry логика.

- **Фронтенд**: `public/index.html`, `public/chat.js`, `public/styles.css`
  - Чат с локальной историей (`localStorage`) до 100 сообщений.
  - Предпросмотр загруженных файлов (имя, размер, изображение).
  - Кастомный Markdown‑рендерер с безопасным экранированием.
  - Typing‑эффект для ответов ассистента.
  - Фиксированный layout: header + chat + footer по высоте экрана; скролл только внутри ленты сообщений.
  - Кнопки прокрутки вверх/вниз внутри окна чата.
  - Сворачиваемый блок «Размышление модели» (reasoning) в ответах ассистента.
  - Прогресс-бары с таймером и статусом.
  - Мобильная панель ввода с авто-скрытием.
  - Выпадающее меню для выбора версии документации.

## 2. Принципы моей разработки

1. **Минимально инвазивные изменения**
   - Я не переписываю большие куски кода без необходимости.
   - Все правки вносятся точечными патчами (`apply_patch`), с сохранением уже настроенных команд и деплой‑логики.

2. **Сохранение рабочей инфраструктуры**
   - Разделы README про `git`, команды деплоя, GitHub Actions и Cloudflare Wrangler не трогаются, а только дополняются.
   - Предполагается, что основной рабочий поток — через ветку `main` и GitHub Actions.

3. **UX‑ориентированность**
   - Сначала исправление критичных UX‑проблем (layout, прокрутка, читаемость Markdown), затем — новые функции.
   - Особое внимание: большие проповеди и духовные тексты должны комфортно читаться в чате.

4. **Безопасность и конфиденциальность**
   - Никакие ключи и секреты не попадают в репозиторий.
   - Вся интеграция с внешними API строится вокруг уже существующей схемы секретов (Cloudflare/ GitHub Secrets).

5. **Пошаговое развитие**
   - Каждое изменение логически завершено: после правки UI или бэкенда чат должен оставаться сразу рабочим.

## 3. Текущий статус по фронтенду

Сделано:

- **Каркас по высоте экрана**:
  - `html, body` фиксированы по высоте 100%, `body` без общего скролла.
  - `header` и `footer` компактны, с фиксированной высотой (flex: `0 0 auto`).
  - `.chat-container` занимает всё пространство между ними, `.chat-messages` — единственное место со скроллом.

- **Прокрутка и кнопки**:
  - Кнопки `scroll-to-top` и `scroll-to-bottom` привязаны к контейнеру `.chat-messages`.
  - Логика показа/скрытия зависит от положения внутри ленты сообщений, а не страницы.

- **Markdown и читаемость**:
  - Уменьшен шрифт и межстрочные интервалы в сообщениях.
  - Сильно ужаты отступы вокруг заголовков, списков, цитат, разделителей и блоков кода.
  - Ограничено количество подряд идущих `<br>` (максимум два), чтобы не было огромных пустых блоков.

- **Размышления модели (reasoning)**:
  - Ответы ассистента разбиваются на две части: размышление (до тега `</think>` или до первого крупного заголовка) и основная проповедь.
  - Размышление показывается в сворачиваемом блоке `<details class="reasoning-block">` с заголовком «Размышление модели», по умолчанию скрыто.

## 4. Текущий статус по бэкенду

Сделано/поддерживается:

- Нормализация ответов от Cloudflare, Google и OpenRouter в единый формат.
- Повышены лимиты токенов (`max_tokens` / `maxOutputTokens`) до 4096 для длинных ответов.
- Обработка ошибок OpenRouter с пользовательским сообщением «Ошибка OpenRouter: ...».
- Поддержка Telegram webhook в одном воркере вместе с веб‑чатом.
